# OCEAN Figure 8 Runner Design

## Goal

Add the missing executable runner for Figure 8 so the existing Figures 6--9
collector can execute the GROMACS PEPSIN matrix instead of relying on committed
logs or hard-coded timings. The runner must support the paper's two backend
labels, SHM and TCP, and the exact thirteen plotted policy categories.

This change delivers code only. It does not launch GROMACS, QEMU, a VM, or
CXLMemSim while being developed or verified.

## Interface

The runner lives at `workloads/gromacs/run_figure8.sh`, matching the existing
`fig8.command` in `script/figures_6_9/config.example.toml`.

It accepts exactly one Figure 8 cell per invocation:

```text
./run_figure8.sh --backend SHM --policy Baseline
```

The existing collector owns the full 2 x 13 x repetition sweep, raw log names,
CSV normalization, manifest generation, validation, and plotting. This keeps
the new script small and preserves the current artifact schema.

## Inputs

The script resolves its tools from environment variables with repository-local
defaults where possible:

- `FIG8_CXLMEMSIM`: policy-capable `cxlmemsim_legacy` executable.
- `FIG8_GMX_MPI`: MPI-enabled GROMACS executable.
- `FIG8_TPR`: PEPSIN `benchMEM.tpr` input.
- `FIG8_STEPS`: number of MD steps, default `10000`.
- `FIG8_NTOMP`: OpenMP threads per MPI rank, default `1`.
- `FIG8_CPUSET`: CPU list passed to CXLMemSim, default `0`.
- `FIG8_PEBS_PERIOD`: PEBS sampling period, default `1000`.
- `FIG8_SHM_LAUNCHER` and `FIG8_TCP_LAUNCHER`: executable backend adapters.

Each backend adapter receives the complete policy-run command after `--`. This
is deliberate: the current OCEAN GROMACS shim implements DAX/shared-memory
fallback but does not implement a TCP client, while the current server supports
SHM/TCP without exposing the legacy policy selection interface. Requiring two
explicit adapters prevents the script from silently labeling two identical
runs as SHM and TCP. A launcher may start or connect to the appropriate server,
enter a VM, and then execute the supplied command.

The runner fails closed when any executable/input/launcher is missing. It never
substitutes paper-digitized, historical, or synthetic timing values.

## Policy Mapping

The policy label maps to the four legacy policy slots in allocation, migration,
paging, caching order:

| Label | Legacy tuple |
|---|---|
| Baseline | `none,none,none,none` |
| Interleave | `interleave,none,none,none` |
| NUMA | `numa,none,none,none` |
| Frequency | `none,frequency,none,none` |
| PageTableAware | `none,none,pagetableaware,none` |
| FIFO | `none,none,none,fifo` |
| HeatAware | `none,heataware,none,none` |
| Hybrid | `none,hybrid,none,none` |
| Locality | `none,locality,none,none` |
| CacheFrequency | `none,none,none,frequency` |
| HugePage | `none,none,hugepage,none` |
| Lifetime | `none,lifetime,none,none` |
| LoadBalance | `none,loadbalance,none,none` |

## Execution and Output Contract

The cell runner constructs a shell-safe argument array for `cxlmemsim_legacy`.
Only the target command passed to `-t` is serialized because the legacy CLI
requires that command as one argument. The script sets `HOME`, `PATH`, and
`OMP_NUM_THREADS` for the target, then invokes the selected backend adapter.

Successful output must be the combined CXLMemSim/GROMACS stream and must contain
GROMACS's native completion and positive wall-time markers. The collector
accepts `Finished mdrun` or `Performance:` as native completion evidence and
rejects fatal markers, zero-thread simulator runs, missing completion, and
non-positive timing. The script propagates every nonzero exit status and never
synthesizes a completion marker. SHM and TCP launcher paths must resolve to
distinct executable files.

## Verification

Development verification is non-executing:

1. `bash -n` checks shell syntax.
2. A shell test invokes the runner with fake launcher/tool paths that only
   record argv. It verifies all thirteen mappings, SHM/TCP launcher selection,
   quoting, validation failures, and exit-code propagation without starting the
   workload.
3. Existing Python tests confirm the collector still plans 26 cells per
   repetition and rejects invalid GROMACS logs.

No benchmark result is generated by these checks. A future artifact run uses:

```text
python3 script/reproduce_figures_6_9.py collect --fig 8 --config <config>
python3 script/reproduce_figures_6_9.py plot --fig 8 --input <run-dir>/normalized
```
